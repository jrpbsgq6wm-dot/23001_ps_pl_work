# PS 与 PL Codex 其他沟通

## 1. 用途

本文件用于记录与正式接口协议无关、但有助于双方协作的沟通，例如：

- 如何更高效地协作；
- 当前协作流程是否存在问题；
- 两个 Codex 如何交接工作；
- 文档应该如何组织；
- Git 操作或分支使用疑问；
- 对当前协作思路的建议；
- 对任务范围、工作节奏和分工的疑问；
- 其他不属于寄存器、数据格式和硬件行为的沟通。

这里可以进行开放讨论，不要求每条内容都形成项目决策。

## 2. 与正式接口问题的边界

如果沟通内容会改变以下任何一项，就不能只留在本文件：

- 寄存器地址或位定义；
- 数据帧格式；
- DMA 或 IRQ 时序；
- DSP 输入输出；
- PS 设备树；
- 错误、复位或超时行为；
- 性能指标；
- 显控数据格式。

这类内容必须另外写入：

~~~text
docs/数据链路/
docs/协作记录/
~~~

并在本文件中留下关联编号。

## 3. 记录格式

每个主题使用独立编号，按时间追加：

~~~text
沟通编号：CHAT-001
日期：
发起方：PS Codex / PL Codex
接收方：PS Codex / PL Codex
主题：
问题或建议：
回复：
是否影响项目接口：是 / 否
关联记录：
状态：讨论中 / 已完成 / 转正式接口问题
~~~

## 4. 协作原则

双方都可以查看整个仓库，但仍然遵守目录职责：

- PS Codex 只修改 ps/；
- PL Codex 只修改 pl/；
- 发现对方目录的问题，通过协作记录沟通；
- 不因为讨论方便而直接修改对方文件；
- 不把未经确认的聊天内容当成正式协议；
- 对项目无关的交流可以保留，但不能覆盖正式接口结论。

## 5. 示例

~~~text
沟通编号：CHAT-001
日期：待填写
发起方：PL Codex
接收方：PS Codex
主题：协作记录是否需要每个问题单独建文件
问题或建议：
建议寄存器问题使用独立记录，普通协作问题集中记录在本文件。
回复：
PS Codex 回复后填写。
是否影响项目接口：否
关联记录：无
状态：讨论中
~~~
