# 23001 PS/PL 协作会话与决策裁定规则

版本：1.0  
生效基线：baseline-20260921  
适用仓库：23001_ps_pl_work

## 1. 协作目标

本仓库用于维护 23001 项目的 PS、PL 和接口联调资料。GitHub 仓库是工程状态的唯一事实来源；共享协作会话是接口讨论和决策记录中心；PS、PL 本地会话分别负责各自工程领域。

三个会话不会自动共享聊天上下文。任何需要长期有效的结论，都必须进入 Git 提交、问题记录、接口确认表或测试报告，不能只留在聊天消息中。

## 2. 仓库结构和职责范围

~~~text
20260916_协作/
├── ps/
│   ├── 20260916/       PS 源代码和编译工程文件
│   ├── device-tree/    设备树，目前只放 system.dts
│   └── 其他 PS 文件夹
├── pl/                 PL 配置、寄存器导出和构建说明
├── docs/               接口、问题、决策和联调记录
└── .git/               Git 历史
~~~

### PS 本地会话

PS 会话负责：

- 可以查看整个仓库，包括 pl/ 下的 PL 配置和接口导出；
- 分析和修改 ps/20260916/ 下的 PS 源码；
- 修改 ps/device-tree/ 下的设备树；
- 检查用户态寄存器访问、DMA、UIO、中断和网络上传流程；
- 根据已经确认的 PL 接口实现 PS 代码；
- 提交 PS 编译、运行和硬件测试结果。

PS 会话不得根据未确认的 PL 推测直接修改接口相关代码。

### PL 本地会话

PL 会话负责：

- 可以查看整个仓库，包括 ps/20260916/ 和 ps/device-tree/；
- 分析和维护 pl/ 下的 PL 配置；
- 提供寄存器地址、位定义、数据格式、DMA 配置和中断时序；
- 说明 PL build ID、配置版本和生成方式；
- 根据测试结果修正 PL 配置并提交版本。

PL 会话不得直接修改 ps/20260916/ 或 ps/device-tree/。发现 PS 问题时，通过协作记录通知 PS Codex，由 PS Codex 修改。

### PS/PL 共享集成会话

共享会话负责：

- 汇总 PS 和 PL 双方的问题与结论；
- 为接口问题分配编号并维护状态；
- 判断结论是否具备足够证据进入实现；
- 组织 integration/<topic> 分支的合并和联调；
- 维护 docs/interface/、docs/issues/ 和 docs/test-reports/；
- 将已验证组合合并到 main 并建立版本标签。

共享会话不能凭猜测替代 PS 或 PL 工程师做接口决定。

## 3. Git 分支规则

- main：最近一次通过联调的稳定组合，不直接进行功能开发。
- ps/<issue>：PS 源码和设备树修改。
- pl/<issue>：PL 配置和 PL 接口导出修改。
- integration/<topic>：合并 PS 与 PL 修改并进行验证。

开始工作前执行：

~~~powershell
git fetch --all --prune
git status
git log --oneline --decorate -10
~~~

提交前执行：

~~~powershell
git diff --check
git status
git diff --stat
~~~

禁止强制推送、覆盖他人分支或在两个会话中使用同一个工作目录。一个提交只完成一类明确的事情。

本项目不使用 Pull Request。PS 和 PL Codex 分别推送自己的工作分支，由共享集成会话统一拉取、审查、合并和推送集成分支。只有共享集成会话可以把经过验证的集成分支合并到 `main`。任何 Codex 都不能直接把未验证的修改推送到 `main`。

集成时使用显式的 Git 合并并保留合并记录：

~~~powershell
git fetch origin
git switch integration/<topic>
git pull --ff-only
git merge --no-ff origin/pl/<issue>
git merge --no-ff origin/ps/<issue>
~~~

如果合并发生冲突，先停止合并并记录冲突文件、双方意图和需要工程师裁定的接口问题，不能凭猜测解决关键协议冲突。

提交信息使用以下前缀：

~~~text
ps: ...
pl: ...
docs: ...
test: ...
~~~

## 4. 问题和决策记录

每个接口问题单独建立一个文件，放在 docs/issues/：

~~~text
NREAD-001.md
IRQ-001.md
ROLL-001.md
FREQ-001.md
BUILD-001.md
~~~

问题文件至少包含：

- 问题编号和提出方；
- 基线提交号；
- 清晰的问题描述；
- PS 侧现状和证据；
- PL 侧结论和依据；
- 需要修改的文件；
- 相关 Git 提交号；
- 验证方法和验证结果。

问题状态按以下顺序推进：

~~~text
待确认
  → PL 已说明
  → 双方确认
  → PS 已实现
  → 硬件已验证
~~~

状态含义：

- 待确认：问题已提出，不能据此修改正式代码。
- PL 已说明：PL 给出了初步解释，但 PS 和共享会话仍需检查完整性。
- 双方确认：地址、位定义、单位、长度、时序、版本和依据都已明确，可以进入实现。
- PS 已实现：PS 已按确认结论修改代码或设备树，但尚未完成硬件验证。
- 硬件已验证：指定 PS 提交和 PL 配置在目标硬件上验证通过。

## 5. 决策裁定规则

### 5.1 证据优先级

出现不同意见时，按以下顺序判断：

1. 目标硬件上的可重复测试结果；
2. 同一 PL build ID 下的寄存器读写和 DMA/IRQ 日志；
3. PL 配置导出、寄存器表、地址映射和构建脚本；
4. PS 源码、设备树和实际读取结果；
5. 已提交的接口文档；
6. 聊天中的口头描述或推测。

低优先级信息不能推翻更高优先级的可复现实证。

### 5.2 结论必须可执行

“应该这样”“大概是”“理论上可以”不能作为最终接口结论。正式结论必须明确：

- 寄存器或内存地址；
- 位域和数据类型；
- 单位和换算公式；
- 写入或读取时机；
- 数据长度和对齐规则；
- 中断产生、清除和确认顺序；
- PL build ID 或配置版本；
- 验证方法。

### 5.3 分歧处理流程

1. 在对应问题文件中记录双方意见，不在聊天中反复口头争论。
2. 由提出方列出最小复现条件和需要补充的证据。
3. PL 侧优先补充配置、寄存器和时序证据；PS 侧优先补充代码路径、读取日志和设备树证据。
4. 共享会话将结论标记为“待确认”或“双方确认”，不能使用模糊状态。
5. 证据不足时保持“待确认”，暂停相关实现；不能用猜测填补接口空白。
6. 如果双方仍然无法一致，建立一个最小实验，只改变一个变量，并把结果写入 docs/test-reports/。
7. 实验结果产生后，以可重复的硬件结果作为裁定依据。

### 5.4 紧急修复

如果设备已经出现严重故障，需要临时绕过接口问题：

- 必须使用独立分支；
- 提交信息中标记 temporary；
- 在问题文件中写明绕过的假设、风险和回滚方式；
- 临时修改不能直接成为 main 的长期协议；
- 验证完成后必须补齐正式接口结论或回滚临时实现。

## 6. 典型协作流程

以 NREAD-001 为例：

1. PS 会话在 docs/issues/NREAD-001.md 记录当前代码和疑问。
2. PL 会话在 pl/NREAD-001 分支核对配置和时序。
3. PL 提交配置、接口说明和问题结论，并推送分支。
4. 共享会话检查地址、长度、时序、build ID 和证据，确认问题状态。
5. 状态变为“双方确认”后，PS 会话创建 ps/NREAD-001 分支实现代码和设备树。
6. 共享会话在 integration/NREAD-001 合并 PL 与 PS 分支。
7. 编译、烧录和硬件验证，并写入 docs/test-reports/。
8. 验证通过后合并到 main，建立新的版本标签。

## 7. 统一消息格式

共享会话中的每条重要消息使用以下格式：

~~~text
问题编号：NREAD-001
提出方：PS / PL / 共享集成
当前基线：main@<commit>
相关分支：pl/NREAD-001
结论状态：待确认 / PL 已说明 / 双方确认 / PS 已实现 / 硬件已验证
问题或结论：
证据文件或日志：
需要对方完成的动作：
~~~

GitHub Issue、分支、问题文件和提交信息中的编号必须保持一致，便于从接口结论追溯到代码和测试结果。GitHub Issue 只用于问题讨论和工程师裁定，不作为代码合并通道。

## 8. 版本发布规则

main 只接受已经完成代码审查和必要验证的组合。发布前必须记录：

- PS 提交号；
- PL build ID 和配置提交号；
- 设备树版本；
- 编译结果；
- 硬件测试报告；
- 已知限制和未关闭问题。

发布使用带日期的标签，例如：

~~~text
pspl-20260921-r1
~~~

当前共同基线为：

~~~text
baseline-20260921
~~~


## 当前数据链路重构模式

本次只重构“湿端 IQ → PL → DSP → PL → PS → 显控”链路，不重构其他业务模块。

当前使用一个共享分支：

~~~text
main                  稳定基线
rewrite/data-path     PS Codex 与 PL Codex 共同工作的重构分支
~~~

PS Codex 和 PL Codex 在各自电脑上克隆同一个仓库，并在工作前拉取、工作后提交和推送。双方都可以查看整个仓库；PS Codex 只修改 ps/20260916/ 和 ps/device-tree/，PL Codex 只修改 pl/。双方通过 docs/数据链路/ 和 docs/协作记录/ 交换接口、问题和回复。任何一方发现对方目录的问题，都必须由目录所属 Codex 修改。

PL Codex 先提交寄存器、数据帧、DMA、中断和 DSP 接口定义；PS Codex 拉取后完成 UIO、设备树、寄存器结构、数据接收和显控上传。如果 PS 不理解 PL 字段，必须记录问题并等待 PL Codex 回复，不能凭猜测实现。

该分支验证通过后，才允许合并到 main。
